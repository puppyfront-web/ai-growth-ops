# 真实平台逐账号验收 Runbook

状态：待执行（等待用户提供低风险测试账号与书面批准）
适用：`spec/11` 实施结果清单中"真实平台发送/回复"与"小红书真实账号主动获客"两项验收。
原则：遵守 `AGENTS.md` 第 9/10 节——未经书面批准不得向真实平台发送；无外部证据不得把能力标为已验证。

## 0. 为什么需要这个流程

自动化测试（单元/集成/E2E）只证明代码路径正确，不证明平台真实可用。按平台能力诚实原则，`verified` 状态必须由"授权账号完成真实动作 + 保留外部 ID/时间/截图/日志"支撑。本 Runbook 把验收动作收敛为最小集合：每个能力一次真实动作。

## 2. 书面批准模板（复制填写后存档到本目录）

```text
真实平台验收批准单
日期：____
批准人（业务负责人）：____（姓名/角色）
执行人：____

批准执行的动作用真实账号各完成一次，对象均为测试数据：
1. 抖音测试账号「____」对一条测试评论/私信发送一条真实回复；
2. 将一个测试客户真实写入飞书多维表格「____」；
3. （可选）小红书测试账号「____」执行一次低量关键词采集（≤3 视频）。

不批准的范围：主账号发布、批量发送、真实客户数据写入、任何未列出的动作。
撤销条件：出现风控提示/验证码即停止，剩余动作作废。
```

## 3. 验收步骤与证据要求

### 3.1 抖音真实回复（关闭"真实平台发送/回复"项）

1. 扫码登录测试账号，确认健康检查通过。
2. 同步一条测试评论/私信（评论私信 → 同步）。
3. 在审核队列对该互动执行一次回复（人工确认后发送）。
4. 记录证据：

| 证据 | 内容 |
| --- | --- |
| 外部回复 ID | `reply_attempts.external_reply_id` |
| 发送时间 | `reply_attempts.created_at` |
| 平台截图 | 评论区显示该回复的截图 |
| 日志 | API/Worker 日志片段（无密钥） |
| 失败路径 | 若失败：错误码 + 恢复指引是否清晰 |

5. 验收通过后：能力矩阵 `douyin.reply` 由 `beta` → `verified`（`packages/shared/src/platform-capabilities.ts`），同步更新 `docs/delivery/crm-release-status.md` 与本文件状态，并补充 `tests/unit/shared/platform-capabilities.test.ts` 断言。

### 3.2 飞书真实写入（关闭 P0 交付记录中的阻断项）

1. 配置飞书多维表格（集成 → 同步与推送）。
2. 创建一个测试客户，点击"同步飞书"。
3. 在飞书表格中核对新增行与字段。
4. 记录证据：`LeadExternalMapping.externalId`、`externalUrl`、同步时间、表格截图、失败重试路径说明。
5. 通过后更新 `crm-release-status.md` 的"真实平台"一节。

### 3.3 小红书低量采集（关闭"小红书真实账号主动获客验收"项）

1. 扫码登录小红书测试账号。
2. 创建获客任务：平台选"小红书（Beta，需确认）"，勾选风险确认，预算 ≤3 视频。
3. 执行并等待完成，核对候选与证据。
4. 记录证据：任务 ID、视频/评论数、候选截图、验证码/中断时的行为记录。
5. 通过后：`xiaohongshu.prospecting` 由 `beta` → `verified`，并从 `PROSPECTING_BETA_PLATFORMS` 移入默认平台列表（仍需低量灰度一周）。

### 3.4 抖音评论回复（manual-reply 低量真实验收模板）

> 目标：对一条真实评论，通过 `manual-reply` 链路发送一条人工确认的回复，关闭"抖音评论真实回复"验收项。本模板与 3.1 的区别：3.1 是通用要求，本模板给出可直接执行的步骤与判定标准。

#### 批准单（复制填写后与证据同目录存档）

```text
抖音评论回复真实验收批准单
日期：____
批准人（业务负责人签字）：____
执行人：____
测试账号：抖音「____」
目标评论：本账号视频（externalPostId ____）下由测试人员留下的评论 ____
批准动作：通过 manual-reply 对该评论发送一条人工确认的回复，共 1 条。
不批准的范围：其余任何评论、批量发送、主账号。
撤销条件：触发验证码/风控提示立即停止。
```

#### 前置条件

| # | 条件 | 校验方式 |
| --- | --- | --- |
| 1 | 账号健康检查通过 | 集成 → 平台账号，状态 `active` 且健康检查 `valid: true` |
| 2 | 评论作者不在黑名单 | 评论私信 → 列表，该评论无"黑名单"标签；黑名单机制上线前（见 `spec/47`）由执行人人工确认作者非退订/投诉用户并在此注明：____ |
| 3 | 频控配置就绪 | 设置 → 自动回复：每日上限 ≥1、当前发送量未触顶、不在静默时段 |
| 4 | 目标评论已同步入库 | 评论私信 → 同步，执行一次手动同步并能在列表看到该评论 |

#### 执行步骤

1. Web：评论私信 → 互动列表，打开目标评论详情。
2. 点击"生成回复建议"，人工编辑确认回复内容（人工确认是硬性要求，不得直接发送未审内容）。
3. 点击"发送回复"（触发 `POST /api/interactions/:id/reply`），等待返回结果。
4. 在抖音 App 评论区核对回复可见。

#### 证据要求

| 证据 | 内容 |
| --- | --- |
| 外部回复 ID | `reply_attempts.external_reply_id` |
| 时间戳 | `reply_attempts.created_at`（含时区） |
| 截图 | 抖音评论区显示该回复的截图（含评论上下文） |
| 日志位置 | API/Worker 日志片段（`interaction.manual-reply` 任务），注明文件路径与行号，不含密钥 |
| 审计记录 | `AuditLog` 中本次人工确认发送的记录 |

#### 失败路径与回滚

- 发送失败（网络/平台错误）：`reply_attempts` 落失败记录，核对错误码与恢复指引是否清晰；不自动重试，人工排查后需新批准单再试。
- 被限流/风控：立即停止，记录现象与日志，本次验收作废，账号冷却至少 24 小时；不得更换路径重试绕过。
- 回复内容有误：无法撤回时在评论区手动删除该回复，并在证据目录记录删除操作与原因。

#### 验收判定标准

- 同时满足才算通过：API 返回成功且 `external_reply_id` 非空；抖音评论区人工核对可见；证据五项齐全；失败路径（若触发）有明确错误码与处置记录。
- 通过后：能力矩阵 `douyin.reply` 的评论子项按第 3.1 节流程升级 `verified`，同步更新 `crm-release-status.md` 与本文件第 5 节状态表。

### 3.5 抖音私信回复（低量真实验收模板）

> 目标：对一条真实私信，通过人工确认链路发送一条回复，关闭"抖音私信真实回复"验收项。

#### 批准单（复制填写后与证据同目录存档）

```text
抖音私信回复真实验收批准单
日期：____
批准人（业务负责人签字）：____
执行人：____
测试账号：抖音「____」
目标会话：测试人员用另一账号向测试账号发起的私信会话 ____
批准动作：对该会话发送一条人工确认的回复，共 1 条。
不批准的范围：其余任何会话、批量发送、主账号。
撤销条件：触发验证码/风控提示立即停止。
```

#### 前置条件

| # | 条件 | 校验方式 |
| --- | --- | --- |
| 1 | 账号健康检查通过 | 同 3.4 前置条件 1 |
| 2 | 私信对方不在黑名单 | 同 3.4 前置条件 2（黑名单机制上线前人工确认） |
| 3 | 频控配置就绪 | 同 3.4 前置条件 3，私信与评论共用 org 级频控 |
| 4 | 目标私信已同步入库 | 评论私信 → 私信列表，手动同步后能看到该会话 |

#### 执行步骤

1. Web：评论私信 → 私信列表，打开目标会话详情。
2. 点击"生成回复建议"，人工编辑确认回复内容（人工确认是硬性要求）。
3. 点击"发送回复"（触发 `POST /api/interactions/:id/reply`），等待返回结果。
4. 在抖音 App 私信中核对回复可见。

#### 证据要求

| 证据 | 内容 |
| --- | --- |
| 外部回复 ID | `reply_attempts.external_reply_id` |
| 时间戳 | `reply_attempts.created_at`（含时区） |
| 截图 | 抖音私信会话显示该回复的截图（注意脱敏对方昵称/头像） |
| 日志位置 | API/Worker 日志片段（`interaction.manual-reply` 任务），注明文件路径与行号，不含密钥 |
| 审计记录 | `AuditLog` 中本次人工确认发送的记录 |

#### 失败路径与回滚

- 发送失败：同 3.4，不自动重试；错误码与恢复指引必须可复现。
- 被限流/风控：立即停止并冷却，作废本次验收；私信风控严于评论，冷却不少于 48 小时。
- 对方明确表示退订/拒绝：立即停止后续任何私信动作，并在黑名单机制上线后加入黑名单（`spec/47` 目标 G1）；当前先人工登记到本模板证据目录。

#### 验收判定标准

- 同时满足才算通过：API 返回成功且 `external_reply_id` 非空；抖音 App 私信人工核对可见；证据五项齐全（截图已脱敏）；失败路径（若触发）有明确错误码与处置记录。
- 通过后：能力矩阵 `douyin.reply` 的私信子项按第 3.1 节流程升级 `verified`，同步更新 `crm-release-status.md` 与本文件第 5 节状态表。

## 4. 通用规则

- 任何一步触发验证码/风控：立即停止，记录现象，按失败路径处理，不重试绕过。
- 每个能力只执行批准的次数；重复执行需新的批准单。
- 证据统一存档在 `docs/delivery/acceptance-evidence/<日期>-<平台>-<能力>/`。
- 验收未通过时能力保持 `beta/unverified`，并把失败原因写入 `crm-release-status.md`。
