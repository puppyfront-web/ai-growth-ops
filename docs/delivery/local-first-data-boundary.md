# 本地数据运行规范

## 目标

系统采用单机本地 Runtime。登录、权限、客户、内容、互动、任务、运行记录、素材和第三方凭据全部保存在用户设备，不配置云端控制面或远程业务数据库。只有用户主动调用的第三方平台、邮件和模型接口会收到完成该操作所需的数据。

## 存储边界

`LOCAL_DATA_DIR` 是唯一持久化根目录：

- `postgres/`：账号、权限及全部结构化业务数据。
- `objects/`：MinIO 素材对象。
- `uploads/`：API 上传和生成的本地文件。
- `secrets/`：平台 Cookie、Token 和模型密钥的加密文件。
- `redis/`：本机任务队列状态，可由 PostgreSQL 中的业务状态重建。
- `backups/`：本地一致性备份。

生产 Compose 只向宿主机回环地址暴露 Web 和 API。PostgreSQL、Redis、MinIO 与 Browser Runner 仅在内部网络通信，所有持久卷绑定到 `LOCAL_DATA_DIR`。

## 启动流程

1. 将 `LOCAL_DATA_DIR` 设置为用户控制的绝对路径，不使用网盘同步目录。
2. 执行 `pnpm local:prepare` 创建权限为 `0700` 的目录结构。
3. 执行数据库迁移和种子初始化，再启动完整 Compose。
4. 用普通用户完成登录、客户创建、素材上传、任务执行和重启恢复验证。

## 备份与恢复

`pnpm local:backup` 会暂停写入服务，导出 PostgreSQL，并在 MinIO 停止后归档对象、上传文件和加密凭据，完成后自动恢复服务。恢复命令为 `pnpm local:restore -- <备份目录> --confirm`，它会替换当前本地数据，必须先在隔离目录演练。

`.env` 中的 `TOKEN_ENCRYPTION_KEY` 不放入数据归档，需要由用户单独安全备份；丢失该密钥后本地凭据无法解密。

## 上线门槛

- 断开云端数据库后，注册登录、权限和全部核心业务仍可工作。
- 宿主机除 Web/API 回环端口外没有数据服务端口。
- 重启容器后数据库、素材、上传文件和凭据完整保留。
- 备份恢复后记录数量、素材校验值和一条加密凭据核验一致。
- 删除 `LOCAL_DATA_DIR` 后设备上不再残留业务数据；该操作只由用户明确执行。
