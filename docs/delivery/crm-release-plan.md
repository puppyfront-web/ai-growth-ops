# 实施计划与验收用例

关联规范：[crm-release-spec.md](./crm-release-spec.md)。最终证据和未完成项见 [crm-release-status.md](./crm-release-status.md)。

## 顺序

1. 保存当前工作区基线，核对类型/lint；修正测试隔离，先用无数据库测试验证保护，再运行集成测试。
2. 删除无引用 Chat 工具工厂；API 与 Worker 共用 LLM 解析；统一模型入口，保留媒体配置与旧 URL。
3. 合并日历和素材来源视图；修复相关页面的数据加载行为，旧链接兼容。
4. 修复本轮发现的配置越权和凭据暴露问题；补失败回归及成功路径测试。
5. 执行类型、lint、构建、单元、集成、关键 E2E；保存命令、退出码与输出，不将未执行标成通过。
6. 根据失败项排列阻断清单；按规范完成真实平台和部署演练后才能签收生产交付。

## 关键测试

| 场景 | 预期 |
| --- | --- |
| 数据库名只在密码、主机、查询参数中出现 e2e 字样 | 拒绝执行 |
| e2e 名称带后缀或编码绕过 | 拒绝执行 |
| 标准业务库 URL 转测试 URL | 只修改数据库名，凭据不输出 |
| 测试 Redis 隔离 | 不向默认应用 DB 写入队列 |
| viewer/member 修改模型配置 | 403；管理员允许 |
| 浏览器持登录令牌读取 internal 密钥接口 | 403；缺失服务凭据时关闭 |
| 组织模型配置读取 | API/Worker 共用解析、组织过滤、密钥只在服务端解密 |
| 空密钥保存 | 保留已有密钥；公开响应不含原始值 |
| 日历从 loading 切到有数据 | 正常渲染，不改变 Hook 调用顺序 |
| 旧日历/素材文件夹地址 | 到达统一页面，不丢内容与发布视图 |

## 后续迁移（不是直接删除）

执行器收敛须先盘点在途 CampaignRun/WorkflowExecution/AgentRun，映射状态和审批记录；暂停新旧双写，进行影子执行比较，再按组织切换、观察与回滚。Lead/Customer 合并只收敛入口，历史来源、外部映射、统计口径和同步记录需保留。

发布前由交付负责人准备部署域名、实际平台/飞书测试对象和备份目标；工程负责人执行命令与故障恢复，业务负责人核对真实客户来源与统计，最终按状态文档逐项签收。
