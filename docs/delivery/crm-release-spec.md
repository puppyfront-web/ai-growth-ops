# 获客 CRM 整理与交付规范

状态：实施中，未达到上线验收。本文是当前收敛范围；历史 spec 保留为设计来源，不代表全部承诺交付。

## 产品目标

面向单公司运营团队，把平台公开互动转为可追踪的潜在客户，辅助内容发布与人工跟进。主要闭环：关键词搜索 → 候选筛选 → 客户入库 → 跟进记录 → 飞书同步 → 获客统计。内容发布 → 评论私信 → 客户转化是第二条获客路径。

默认交付形态为受控团队试用；公网生产发布必须另行通过部署、安全及真实平台验收。未验证的平台不宣称稳定可用。

## 范围与兼容

- 核心：关键词获客、客户管理、内容与发布、评论私信、获客分析、配置。
- Lead 保留平台来源与转化证据，Customer 是运营主入口；不删历史表、不丢来源关系。
- 素材上传与审核保留；来源分类并入素材列表。生图/视频、市场调研、通用聊天、驾驶舱列为扩展能力。
- 合并日历视图，旧地址重定向。模型配置统一到组织级 LLM 配置，媒体配置独立保留；旧配置兼容迁移必须保留密钥且避免跨组织继承。
- Campaign、Workflow、Runtime 暂保留兼容执行。新增业务优先复用现有领域任务；只有幂等、重试、审批、恢复及历史任务迁移通过后才能删除旧执行器。
- 清理无调用工具副本，复用共享模型解析。不引入新的通用编排框架。

## 工程规则

遵循现有风格、SOLID 与单一事实来源；禁止以 any、禁用检查或吞掉错误伪造通过。先补边界回归，再修逻辑。配置、凭据、权限、去重、任务恢复属于有行为测试的变更；简单重定向不写镜像实现的测试。

测试只能连接精确命名的 ai_growth_ops_e2e 数据库；Redis 使用独立测试 DB，不与应用 Worker 共用队列。禁止输出密钥、重置业务库或用真实发布/发送消息替代自动化测试。

## 上线门槛

| 门槛 | 必须提供的证据 |
| --- | --- |
| 工程 | 类型、源码 lint、构建、单元与集成测试通过；遗留错误不能被新模块通过掩盖 |
| 用户闭环 | 浏览器验证关键词任务、筛选、去重入库、客户详情、跟进、筛选统计；失败提示能指导恢复 |
| 安全 | 非管理员不能修改组织配置；跨组织读写被拒；HTTP 不向普通会话返回密钥；生产无默认密码与公开内部服务 |
| 可靠性 | 同一候选重复转化不重复建客户；任务重试不会重复发布/同步；账号失效明确标记并可恢复 |
| 真实平台 | 授权账号低量完成采集；人工批准一条内容发布/回复与飞书同步，保留时间、外部 ID、截图和失败记录 |
| 运维 | 数据库迁移、上传文件与密钥备份恢复、Worker 重启恢复、健康检查及回滚演练通过 |

任何 P0/P1 未解决或关键证据缺失，结论为不满足生产上线；Mock/E2E 通过只能证明对应范围。真实发帖、回复和对外同步必须使用明确批准的测试对象。
