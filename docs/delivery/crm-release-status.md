# CRM 交付状态

评估日期：2026-09-23
当前结论：**单机本地数据边界的代码与真实平台核心闭环已验证（真实账号采集、语义打分、画像增强、一条真实发布），剩余回复/飞书写入、本地恢复演练和稳定性观察后即可上线。** 数据规范见 [local-first-data-boundary.md](./local-first-data-boundary.md)。

## 已完成的整理

- 主入口收敛为智能获客、客户、内容与发布、评论私信、获客分析、集成和设置；旧日历与素材文件夹地址保留重定向。
- 智能获客改为自然语言需求输入，经结构化意图识别生成多策略计划；计划由服务端短期保存，确认后按策略预算采集并保留跨策略证据。
- Customer 作为运营入口，Lead 保留来源和转化证据；重复客户、互动转客户、飞书映射和获客统计使用同一业务链路。
- 组织级文本模型配置成为唯一服务端来源；媒体模型配置独立保留。普通登录会话不能读取内部明文密钥，非配置管理员不能修改组织模型配置。
- 删除 Web Chat 中未使用的领域工具副本，API 与 Worker 复用数据库包中的模型解析；旧 Workflow 执行链仅作为有登记的兼容能力保留。
- 测试数据库和 Redis 使用精确隔离目标，数据库重置增加双重保护；补齐可从空库重放的迁移链和既有数据库升级指南。
- 生产 Compose 只把 Web/API 绑定到本机回环地址，内部服务不暴露宿主机端口；生产密码和服务密钥改为必填，镜像使用锁文件构建。
- 登录权限、业务数据库、队列、对象、上传文件和加密凭据统一绑定到用户的 `LOCAL_DATA_DIR`；云端控制面配置已移除，并提供本地目录初始化、备份和恢复命令。
- 真实 LLM 验证修复：意图计划编译增加逐字段矫正层与带反馈重试（推理型模型输出 budget 数字、null 列表、查询超限等偏差不再打断主链路）；技能运行器给足推理模型 token 预算并增加解析失败重试；Worker 素材路径解析与本地数据目录对齐。

## 生产上线阻断项

1. **本地恢复演练**：在隔离的 `LOCAL_DATA_DIR` 执行备份与恢复，核对表行数、组织归属、客户/线索关系、素材文件和密钥解密，再完成一次重启恢复。
2. **真实平台闭环**：为每个声明支持的平台准备低风险测试账号；先完成登录健康检查和少量多策略需求采集，再由业务负责人明确批准一条发布、一条回复和一次飞书同步，记录外部 ID、时间、截图及失败原因。
3. **本机运行演练**：按 [deployment.md](../deployment.md) 配置绝对数据目录和独立强密钥；启动后验证健康检查、Worker 中断恢复、磁盘容量和备份可恢复性。
4. **稳定性观察**：在目标设备连续运行至少一个完整业务日，覆盖定时任务和队列重试；期间出现重复发布、重复客户、任务永久运行、跨组织数据或凭据暴露时立即停止上线。

## 签收顺序

1. 工程负责人执行 `pnpm verify:release`、镜像构建和 Compose 配置校验，保存退出码与版本标识。
2. 数据负责人使用隔离的本地数据目录完成恢复演练，提交校验表、耗时和回滚结果。
3. 业务负责人完成真实平台低量验收，确认客户来源、内容、回复和获客统计一致。
4. 运维负责人完成最小暴露、磁盘检查、备份副本与目标设备观察；所有阻断项关闭后，将本文结论改为可上线并签署版本号。

任何一步没有证据都保持“未验收”，不能用单元测试、Mock 或空库迁移结果代替。
