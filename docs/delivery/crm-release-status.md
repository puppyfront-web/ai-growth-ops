## 已完成的整理

- 主入口收敛为关键词获客、客户、内容与发布、评论私信、获客分析、集成和设置；旧日历与素材文件夹地址保留重定向。

- 组织级文本模型配置成为唯一服务端来源；媒体模型配置独立保留。普通登录会话不能读取内部明文密钥，非配置管理员不能修改组织模型配置。
- 删除 Web Chat 中未使用的领域工具副本，API 与 Worker 复用数据库包中的模型解析；旧 Workflow 执行链仅作为有登记的兼容能力保留。
- 测试数据库和 Redis 使用精确隔离目标，数据库重置增加双重保护；补齐可从空库重放的迁移链和既有数据库升级指南。
- 生产 Compose 只把 Web/API 绑定到本机回环地址，内部服务不暴露宿主机端口；生产密码和服务密钥改为必填，镜像使用锁文件构建。

## 生产上线阻断项

1. **已有数据升级**：按 [database-upgrade.md](./database-upgrade.md) 将生产备份恢复到隔离数据库，形成专属升级 SQL，核对表行数、组织归属、客户/线索关系、外部映射和密钥解密，再完成一次恢复回滚。
2. **真实平台闭环**：为每个声明支持的平台准备低风险测试账号；先完成登录健康检查和少量关键词采集，再由业务负责人明确批准一条发布、一条回复和一次飞书同步，记录外部 ID、时间、截图及失败原因。
3. **生产运行演练**：按 [deployment.md](../deployment.md) 配置域名、TLS、独立强密钥和外部备份目标；启动后验证健康检查、日志告警、Worker 中断恢复、磁盘容量和备份可恢复性。
4. **稳定性观察**：在预生产环境连续运行至少一个完整业务日，覆盖定时任务和队列重试；期间出现重复发布、重复客户、任务永久运行、跨组织数据或凭据暴露时立即停止上线。

## 签收顺序

1. 工程负责人执行 `pnpm verify:release`、镜像构建和 Compose 配置校验，保存退出码与版本标识。
2. 数据负责人在生产副本完成升级和恢复演练，提交校验表、耗时和回滚结果。
3. 业务负责人完成真实平台低量验收，确认客户来源、内容、回复和获客统计一致。
4. 运维负责人完成 TLS、最小暴露、告警、外部备份与预生产观察；所有阻断项关闭后，将本文结论改为生产可上线并签署版本号。

任何一步没有证据都保持“未验收”，不能用单元测试、Mock 或空库迁移结果代替。
