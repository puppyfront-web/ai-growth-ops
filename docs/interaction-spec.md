# 交互规范（Interaction Spec）

> 状态：生效中（2026-10-14 起）
> 适用：apps/web 全部页面与组件
> 上游：docs/ui-ux-upgrade-plan.md B1。视觉规范见 docs/ui-redesign-plan.md 第 3 节。

本文件是全站交互决策的单一事实来源。新增/修改页面时按此执行；代码评审按此验收。

## 1. 成功反馈三档

| 场景 | 形式 | 实现 |
|---|---|---|
| 轻操作（标记已读、改状态、点赞类） | toast 轻提示 | `toast.success('已标记为已读')` |
| 创建/编辑完成 | `router.push` 到详情/列表 + 目标页可感知结果 | **禁止** `window.location.href`（整页刷新丢滚动位置、闪屏、慢） |
| 后台长任务（获客任务、发布） | 跳转任务详情页看行内进度；完成后 toast 可点击跳转 | 轮询/订阅由页面自管 |

**唯一豁免**：登出与会话失效（`AuthProvider` 登出、`lib/api/client.ts` 401 跳登录）保留整页跳转——这是状态重置而非导航。

## 2. pending 纪律

- 操作进行中**只禁用触发它的那个按钮**（按钮内 spinner 或「处理中…」文案）。
- 禁止整页/整卡片/全部按钮禁用（历史反例：审核页一个请求 pending 锁死全部卡片）。
- 表格行内操作：pending 时该行按钮禁用，其余行不受影响。
- 提交表单：提交按钮 pending + 表单字段只读，但允许「取消」。

## 3. 破坏性操作分级

| 级别 | 定义 | 交互 |
|---|---|---|
| L1 可撤销 | 后果轻、可恢复（标记已读、删除草稿、移除筛选） | **免确认**，操作立即执行 + toast 带「撤销」按钮（6s），见 `ui/toast.tsx` 的 `action` 选项 |
| L2 常规删除 | 不可直接撤销但影响面小（删任务、删内容） | `ConfirmDialog` 一次确认，按钮文案写明对象（「删除任务」而非「确定」） |
| L3 不可逆/影响他人 | 解绑平台账号、移除团队成员、推送生产配置 | `ConfirmDialog` + 输入确认（输入名称/数字），主按钮 destructive 变体 |

## 4. 键盘与焦点

- 全局快捷键不与输入冲突：焦点在 `input/textarea/select/contenteditable` 时跳过全局监听。
- 图标按钮必须有 `aria-label`；纯图标切换钮加 `aria-pressed`/`aria-expanded`。
- 弹层（Dialog/Drawer/Dropdown）：打开时焦点入内、Esc 关闭、关闭后焦点归还触发元素。
- 全站唯一全局导航快捷键是 ⌘K（GlobalSearch），其他页面级快捷键只允许出现在明确宣传快捷键的界面（如审核队列，页脚展示键位提示）。

## 5. 空态与加载

- 列表/看板空态必须走 `shared/EmptyState`：图标 + 一句话 + 主行动按钮；禁止裸「暂无数据」。
- 路由级加载走 `loading.tsx` 骨架（复用 `DataTableSkeleton`/卡片骨架）；禁止整页 spinner 兜底。
- 错误走 `shared/ErrorState` + 重试；请求失败 toast 文案区分「可重试」（网络类）与「需检查配置」（如 LLM 未配置）。

## 6. 导航与返回

- 详情页必有返回路径（Breadcrumb 或「返回」按钮），禁止死胡同。
- 跨模块跳转必须能回得来；新窗口打开仅用于外链。
- 列表筛选/分页状态写 URL 参数（可分享、刷新不丢）。

## 7. 时间与数字

- 时间统一走 `lib/format.ts` 的 `formatDateTime/formatDate/formatRelativeTime`（24h 内相对时间，超出为 `YYYY-MM-DD HH:mm`）。
- 数字/表格列用 `tabular-nums`；金额与计数右对齐。

## 8. 文案

- 成功提示不加感叹号；错误直接说原因与动作（「保存失败，请重试」，不写「哎呀」）。
- 按钮文案 = 动词 + 宾语（「新建获客任务」），禁止裸「确定/提交」当主行动。
