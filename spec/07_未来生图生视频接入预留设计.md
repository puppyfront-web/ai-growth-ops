# 07. 未来生图 / 生视频接入预留设计 v8

## 1. 设计目标

当前项目不实现真实 AI 生图和 AI 生视频，但需要提前预留扩展能力，避免后续接入时重构内容库、素材库、发布任务和审核流程。

目标：

1. 当前 MVP 主流程不依赖任何多媒体生成服务。
2. 后续可以接入第三方图片/视频生成 API。
3. 后续可以接入客户自有模型服务或私有化 ComfyUI 工作流。
4. 生成素材必须先入素材库和人工审核。
5. 生成失败不能影响内容运营、发布、评论私信、线索和飞书企微沉淀。

---

## 2. 当前版本边界

当前版本只实现：

- 接口定义。
- 能力开关。
- Mock Provider。
- Disabled Provider。
- 生成素材元数据结构。
- 生成素材审核状态机。
- 发布前素材审核校验。

当前版本不实现：

- 真实图片生成模型调用。
- 真实视频生成模型调用。
- ComfyUI 工作流执行。
- 视频剪辑、混剪、字幕、配音、数字人。
- 生成素材自动发布。

---

## 3. 未来 Provider 类型

| Provider                          | 说明                  | 当前状态 |
| --------------------------------- | --------------------- | -------- |
| `MockMediaGenerationProvider`     | 用于开发和测试        | MVP 实现 |
| `DisabledMediaGenerationProvider` | 默认关闭能力          | MVP 实现 |
| `ExternalImageApiProvider`        | 第三方图片生成 API    | 后续扩展 |
| `ExternalVideoApiProvider`        | 第三方视频生成 API    | 后续扩展 |
| `ComfyUIProvider`                 | 私有化图片/视频工作流 | 后续扩展 |
| `CustomerOwnedProvider`           | 客户自有生成服务      | 后续扩展 |

---

## 4. 业务流程

```text
内容计划
→ 选择是否需要生成素材
→ 当前 MVP：Disabled 或 Mock
→ 后续版本：调用 MediaGenerationProvider
→ 生成结果保存到 MinIO
→ 写入 MediaAsset
→ 人工审核
→ 审核通过
→ 关联 ContentItem / ContentVariant
→ 创建 PublishJob
→ 发布到 6 个平台
→ 数据复盘
```

```ts
type MediaAssetSourceType =

  | 'external_url'
  | 'platform_imported'
  | 'mock_generated'
  | 'generated_future';

```

## 6. 发布前校验规则

1. `uploaded` 素材可以直接进入发布校验。
2. `external_url` 素材必须先下载或校验可访问性。
3. `mock_generated` / `generated_future` 素材必须 `approved` 后才能发布。
4. `pending_review` 素材禁止创建发布任务。
5. `rejected` 素材禁止发布。
6. 生成素材发布时必须记录素材来源和审核记录。

---

## 7. 测试要求

1. Disabled Provider 调用必须失败且错误清晰。
2. Mock Provider 只能生成 metadata 和占位文件记录。
3. Mock 生成素材默认 `pending_review`。
4. 未审核素材不能发布。
5. 审核通过后可进入 Mock 发布任务。
6. Provider 异常不能影响主业务服务可用性。

---

## 8. 后续接入真实模型时的必备条件

后续如接入真实生图/生视频，必须先确认：

1. 使用哪家模型或 API。
2. 费用预算和单次生成成本。
3. 品牌视觉规范。
4. 生成内容审核规则。
5. 平台对 AI 生成内容的标识要求。
6. 是否需要内容水印、版权声明或 AIGC 标识。
7. 是否允许自动发布生成素材。
8. 是否需要接入内容安全审核服务。

默认原则：即使后续支持真实生成，生成素材也必须先经过人工审核，不允许直接自动发布。
