# 01. AI 全域内容获客运营系统需求 PRD v8

## 1. 产品概述

### 1.1 产品名称

AI 全域内容获客运营系统。

### 1.2 产品定位

面向单个品牌 / 单家公司自用的 AI 内容获客运营系统，统一支持抖音、小红书、微信公众号、微信视频号、百家号、知乎的文本内容策划、素材管理、图文/视频发布、评论/私信承接、客户意向评估、飞书/企微沉淀和运营复盘。当前版本不实现 AI 生图/生视频，但系统必须预留插件式 Media Generation Provider，方便后续接入第三方生图/生视频 API 或私有化多媒体生成服务。

### 1.3 一句话价值

帮助品牌用更少的人完成多平台内容运营，把图文/视频内容产生的评论和私信自动转化为可跟进线索，并沉淀到飞书和企业微信。

---

## 2. 项目目标

### 2.1 业务目标

1. 降低多平台内容运营成本。
2. 降低图文和视频发布的人力成本。
3. 降低评论和私信漏接率。
4. 自动识别高意向客户。
5. 将线索沉淀到飞书和企业微信。
6. 通过数据复盘降低获客成本。
7. 让单品牌团队可以持续运营抖音、小红书、公众号、视频号、百家号、知乎。

### 2.2 产品目标

1. 一个后台管理 6 个自媒体平台。
2. 支持图文、文章、问答、视频等内容形态。
3. 支持 AI 生成文案、标题、脚本、文章、问答、标签和平台风格改写；当前不实现 AI 生图/生视频，但预留未来插件式接入。
4. 支持自动排期、自动发布、辅助发布、人工确认发布。
5. 支持评论、私信、公众号消息、线索表单的统一入库。
6. 支持 AI 客户意向识别和线索评分。
7. 支持飞书多维表格、飞书群机器人、企业微信沉淀。
8. 支持市场调研、竞品分析、公开评论洞察和选题生成。
9. 支持 Mock 模式全链路验收。

### 2.3 当前 MVP 不包含、但未来预留的能力

当前 MVP 不包括以下能力，代码生成时不得实现真实生成逻辑、真实模型调用或自动发布链路；但必须在架构上预留 Provider 接口、数据模型扩展点、素材审核状态和能力开关：

1. AI 生图：当前不调用 Stable Diffusion、Midjourney、DALL·E、GPT-Image 等图片生成模型；后续可通过 `ImageGenerationProvider` 接入。
2. AI 生视频：当前不调用 Runway、Pika、可灵、Sora 类视频生成模型；后续可通过 `VideoGenerationProvider` 接入。
3. 视频剪辑与合成：不做自动剪辑、混剪、转场、配音、字幕烧录、数字人。
4. 图片设计编辑：不做海报设计、图片改图、商品图生成。
5. 仅做素材管理：图片、封面、视频、附件由用户上传、本地素材库管理或外部链接导入。

系统当前可以生成的是文本类内容：选题、标题、正文、脚本、口播稿、摘要、标签、话题、CTA、回复建议和复盘报告。

未来生图/生视频接入原则：

1. 所有生成能力必须通过独立 Provider 接入，不得写死某个模型。
2. 生成结果必须先进入素材库，状态为 `pending_review`。
3. 运营人员审核通过后，才可被发布任务引用。
4. 生成过程必须记录成本、模型、输入参数、输出文件、审核人、发布时间。
5. 当前代码只需实现接口、状态枚举和 Mock Provider，不实现真实生图/生视频调用。

## 2.4 未来 Media Generation 扩展要求

该能力不是当前 MVP 的业务交付范围，但必须作为架构扩展点进入 Spec。

### 2.4.1 未来支持的生成类型

| 类型               | 当前版本       | 后续版本                           |
| ------------------ | -------------- | ---------------------------------- |
| 图片生成           | 不实现真实调用 | 支持接入外部 API / 私有化服务      |
| 视频生成           | 不实现真实调用 | 支持接入外部 API / 私有化服务      |
| 封面生成           | 不实现真实调用 | 可作为图片生成子能力               |
| 商品图/海报生成    | 不实现真实调用 | 可作为模板化图片生成能力           |
| 视频剪辑/字幕/配音 | 不实现真实调用 | 仅在客户明确要求后作为独立模块评估 |

### 2.4.2 未来生成结果的业务流

```text
运营人员选择生成类型
→ 选择品牌规范 / 内容目标 / 平台 / 素材参考
→ 调用 Media Generation Provider
→ 生成结果保存到 MinIO
→ 写入 MediaAsset
→ 进入人工审核
→ 审核通过后可关联 ContentItem / PublishJob
→ 发布后进入数据复盘
```

### 2.4.3 当前 MVP 必须实现的预留点

1. `MediaAsset.sourceType` 支持 `uploaded / external_url / generated_future / mock_generated`。
2. `MediaAsset.reviewStatus` 支持 `pending_review / approved / rejected`。
3. `ProviderCapability` 预留 `generateImage / generateVideo`。
4. `ProviderRunLog` 可记录未来生成任务。
5. 前端素材库预留“未来 AI 生成”能力开关，但默认隐藏或 disabled。

## 5. 核心业务流程

### 5.1 自动运营主流程

```text
品牌运营目标
→ Research Ops 市场调研
→ AI 生成选题
→ AI 生成图文文案/视频脚本/文章/问答/标题/标签
→ 平台风格改写
→ 合规检查
→ 自动排期
→ 图文/视频发布任务
→ 平台发布 / 辅助发布 / 人工确认
→ 评论/私信/消息同步
→ AI 意向识别
→ AI 回复建议
→ 自动回复或人工确认
→ 生成线索
→ 飞书/企微沉淀
→ 销售跟进
→ 运营复盘
→ 下一轮内容计划
```

### 5.2 市场调研到选题流程

```text
关键词 / 竞品账号
→ MediaCrawler 低频采集公开内容和公开评论
→ AI 分析爆款结构和用户痛点
→ 生成内容机会
→ 进入内容计划
```

### 5.3 评论私信转线索流程

```text
平台评论 / 私信 / 公众号消息
→ Interaction 入库
→ 去重与清洗
→ Lead Scoring Agent 评分
→ Reply Agent 生成回复建议
→ Reply Policy Engine 判断风险
→ 低风险自动回复 / 中高风险人工确认
→ A/B 级线索推送飞书和企微
→ 销售跟进和回写状态
```

## 6. 功能需求

## 6.1 账号管理

### 功能说明

统一管理 6 个平台账号和飞书/企微配置。

### 功能点

1. 添加平台账号。
2. 查看账号授权状态。
3. 查看平台能力矩阵。
4. 配置 Provider 模式：official_api / browser_assist / manual_confirm / mock。
5. 查看账号健康状态。
6. 记录账号登录态、授权过期、异常提醒。
7. 支持禁用某个平台账号。

### 验收标准

- 能创建 6 个平台的账号配置。
- 每个账号能显示支持的能力。
- 无真实授权时可以切换到 Mock 模式。
- 授权异常不会影响其他平台。

---

## 6.2 Content Ops 内容运营

### 功能说明

负责选题、文案/脚本草稿、素材库、平台改写。

### 功能点

1. 内容项目管理。
2. 选题库。
3. AI 生成图文文案，包括标题、正文、标签、CTA；不生成图片。
4. AI 生成视频脚本、标题、简介、封面文案；不生成视频文件。
5. AI 生成公众号文章。
6. AI 生成知乎回答。
7. 平台风格改写。
8. 标签/话题推荐。
9. 封面文案生成。
10. 合规检测。
11. 素材库管理，支持用户上传图片、视频、封面、附件，支持外部素材链接导入。
12. 内容日历。

### 平台内容格式

| 平台       | 图文                   | 视频                       |
| ---------- | ---------------------- | -------------------------- |
| 抖音       | 图集、标题、话题       | 视频、封面、标题、话题     |
| 小红书     | 笔记、图片、标题、标签 | 视频笔记、封面、标题、标签 |
| 微信公众号 | 文章、封面、摘要       | 视频素材/文章内视频        |
| 微信视频号 | 不作为主图文平台       | 视频、封面、描述           |
| 百家号     | 图文文章               | 视频                       |
| 知乎       | 回答/文章              | 预留视频能力               |

### 验收标准

- 同一个选题能生成 6 平台内容版本。
- 每个平台内容版本能单独编辑。
- 图文和视频内容都能关联用户上传或导入的素材。
- 系统不会调用 AI 生图或 AI 生视频模型生成图片/视频文件。
- 合规检测能给出风险等级和修改建议。

---

## 6.3 Publish Ops 发布运营

### 功能说明

管理图文和视频发布任务。

### 发布模式

| 模式           | 说明                           |
| -------------- | ------------------------------ |
| official_api   | 官方 API 自动发布              |
| browser_assist | 浏览器辅助填写，人工确认提交   |
| manual_confirm | 系统生成发布清单，人工手动发布 |
| mock           | 模拟发布，用于开发和验收       |

### 功能点

1. 创建发布任务。
2. 设置发布时间。
3. 选择平台账号。
4. 选择发布模式。
5. 上传图文/视频素材。
6. 发布前校验。
7. 发布任务队列。
8. 发布失败重试。
9. 发布截图记录。
10. 发布结果回填。
11. 发布链接保存。
12. 发布状态流转。

### 发布状态

```text
DRAFT
→ READY
→ SCHEDULED
→ RUNNING
→ WAITING_HUMAN_CONFIRM
→ PUBLISHED
→ FAILED
→ CANCELLED
→ NEED_MANUAL_REPAIR
```

### 验收标准

- Mock 模式下 6 平台图文发布全部通过。
- Mock 模式下 6 平台视频发布全部通过。
- 发布失败能记录原因。
- Browser Assist 能生成操作会话和人工确认节点。
- 任一平台失败不影响其他平台任务。

## 6.4 Conversation Ops 评论私信承接

### 功能说明

统一承接评论、私信、公众号消息、公开互动和手动导入线索。

### 功能点

1. 评论同步。
2. 私信同步。
3. 公众号消息接收。
4. 手动导入互动数据。
5. 统一会话列表。
6. 按平台、账号、内容、线索等级筛选。
7. AI 摘要会话。
8. AI 回复建议。
9. 快捷回复。
10. 人工接管。
11. 回复日志。
12. 风险标记。

### 自动回复策略

| 类型         | 策略                         |
| ------------ | ---------------------------- |
| 低风险 FAQ   | 可自动回复                   |
| 价格咨询     | 默认建议回复，人工确认后回复 |
| 高意向合作   | 必须推送销售                 |
| 投诉/负面    | 必须人工处理                 |
| 敏感行业问题 | 必须人工处理                 |
| AI 低置信度  | 必须人工处理                 |

### 验收标准

- 互动数据能统一入库。
- AI 能生成意向、摘要、建议回复。
- 高风险消息不会自动发送。
- A/B 级线索能自动进入 Lead Ops。

## 6.5 Lead Ops 线索管理

### 功能说明

将评论和私信转换为可跟进客户线索。

### 线索等级

| 等级 | 含义   | 动作                           |
| ---- | ------ | ------------------------------ |
| A    | 高意向 | 飞书提醒 + 企微承接 + 销售跟进 |
| B    | 中意向 | 飞书沉淀 + AI 培育 + 运营关注  |
| C    | 低意向 | 自动回复/标签沉淀              |
| D    | 无效   | 忽略或屏蔽                     |

### 功能点

1. AI 意图识别。
2. 线索评分。
3. 客户标签。
4. 线索去重。
5. 来源内容归因。
6. 负责人分配。
7. 跟进状态。
8. 飞书同步。
9. 企微承接。
10. 导出 Excel。
11. Webhook 推送。
12. 跟进结果回写。

### 验收标准

- 评论/私信能转为 Lead。
- Lead 有来源平台、来源账号、来源内容。
- A/B 级线索能推送飞书和企微。
- 跟进状态能回写到系统。

## 6.6 Research Ops 市场调研

### 功能说明

基于 MediaCrawler 等工具进行低频公开数据调研。

### 功能点

1. 关键词调研。
2. 竞品账号配置。
3. 公开内容采集。
4. 公开评论采样。
5. 爆款内容拆解。
6. 评论痛点聚类。
7. 小红书内容机会分析。
8. 抖音视频评论洞察。
9. 知乎问题和回答调研。
10. 选题机会生成。
11. 内容计划生成。

### 使用边界

允许：

- 采集公开内容。
- 采集公开评论样本。
- 单品牌低频调研。
- 竞品内容分析。
- 用户痛点洞察。

禁止：

- 采集私信。
- 绕过验证码或平台安全机制。
- 高频批量采集。
- 采集非公开数据。
- 自动骚扰用户。
- 对外售卖采集服务。

### 验收标准

- 能创建关键词调研任务。
- 能保存采集结果。
- 能对评论进行 AI 聚类。
- 能生成选题机会。
- 采集失败不影响发布和线索模块。

## 7. 非功能需求

### 7.1 可用性

- Mock 模式必须可完整演示。
- 任一平台失败不能导致系统整体不可用。
- 发布、采集、同步任务必须有重试。
- 任务必须可暂停、取消、人工修复。

### 7.2 安全性

- 平台 Token 加密保存。
- 敏感配置不可明文输出到日志。
- 所有 AI 回复和自动发布必须有审计日志。
- 不允许绕过平台安全机制。

### 7.3 可观测性

- 所有 Provider 调用必须记录输入摘要、输出摘要、耗时、状态、错误。
- Browser Assist 必须保存关键截图。
- 关键任务必须有 trace_id。

### 7.4 数据本地优先

- PostgreSQL 是主数据源。
- 飞书/企微只做同步目标。
- 图片、视频、报告、截图保存到 MinIO。
- AI 运行记录保存到本地。
