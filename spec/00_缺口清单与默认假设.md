# 00. 缺口清单与默认假设

## 1. 当前是否还缺少必要信息？

结论：**不缺阻塞 PRD、架构设计和开发计划的信息**。

当前已经明确的信息包括：

- 系统定位：单品牌 / 单公司自用的 AI 全域内容获客运营系统。
- 必须支持平台：抖音、小红书、微信公众号、微信视频号、百家号、知乎。
- 必须支持内容类型：图文、文章、问答和视频发布；当前版本图片/视频素材由用户上传、本地素材库管理或外部素材导入。
- 当前 MVP 不内置 AI 生图/生视频能力。
- 系统架构必须预留 Media Generation Provider 接口，未来可接入第三方生图/生视频 API 或客户自有多媒体生成服务。
- 必须支持自动运营：选题生成、文案/脚本/标题/摘要/标签生成、平台改写、素材管理、排期、发布、评论/私信承接、线索评估、飞书/企微沉淀、复盘；当前 MVP 不实现 AI 生图/生视频，但要预留未来插件式接入能力。
- 数据策略：本地优先保存，同时支持数据库存储。
- 开源复用方向：MediaCrawler、social-auto-upload、xiaohongshu-mcp-skills、xiaohongshu-skills、Wechatsync、mdnice、ChatGPT-On-CS 等。
- 线索沉淀：飞书和企业微信优先。
- 交付方式：通过 SDD 指导 AI 生成代码，通过 TDD 做功能验证。

因此可以进入 PRD、技术架构、任务拆解和测试设计。

## 2. 上线前必须由客户确认的信息

这些信息不阻塞系统设计，但会影响真实平台接入、话术、测试、部署和未来多媒体生成扩展。

### 2.1 品牌与行业信息

| 信息            |   是否必须 | 默认假设                             |
| --------------- | ---------: | ------------------------------------ |
| 公司/品牌名称   | 上线前必须 | 使用 `Demo Brand`                    |
| 所属行业        | 上线前必须 | 企业服务 / AI 获客服务               |
| 主推产品/服务   | 上线前必须 | AI 内容获客运营服务                  |
| 目标客户画像    | 上线前必须 | 中小企业老板、运营负责人、销售负责人 |
| 客单价/转化路径 |   建议确认 | 评论/私信咨询 → 加企微 → 销售跟进    |
| 禁用词/敏感词   | 上线前必须 | 使用系统默认合规词库                 |
| 标准销售话术    |   建议确认 | 由 AI 根据 FAQ 生成初版              |

| 平台       | 需要确认                                 | 默认处理                                           |

| 百家号     | 开发者配置、登录账号、发布权限           | Browser Assist / Provider                          |
| 知乎       | 机构号/个人号、发布权限                  | Browser Assist + Manual Confirm                    |

| 配置                              |   是否必须 | 说明                       |
| --------------------------------- | ---------: | -------------------------- |
| 飞书应用 App ID / Secret          | 上线前必须 | 用于多维表格写入           |

| 飞书群机器人 Webhook              |   建议必须 | 高意向线索提醒             |

### 2.5 未来生图 / 生视频接入信息

以下信息不影响当前 MVP，但会影响后续 Media Generation Provider 的真实接入。

| 信息             | 是否必须 | 默认处理                                    |
| ---------------- | -------: | ------------------------------------------- |
| 是否需要生图     | 后续确认 | 当前关闭，仅保留接口                        |
| 是否需要生视频   | 后续确认 | 当前关闭，仅保留接口                        |
| 使用外部模型 API | 后续确认 | 支持 OpenAI-compatible / HTTP Provider 扩展 |
| 是否接 ComfyUI   |     可选 | 当前不接，后续可作为私有化 Provider         |
| 素材品牌规范     | 后续必须 | 作为 Brand Guideline 输入，不在 MVP 强依赖  |
| 生成内容审核规则 | 后续必须 | 生图/生视频结果必须进入人工审核队列         |
| 生成成本预算     | 后续必须 | 未来需计费、限额和成本监控                  |

默认原则：当前版本只管理和发布用户已有素材；未来接入生图/生视频时，必须通过独立 `media-generation-provider` 插件接入，生成结果先进入素材库和人工审核，不得直接自动发布。

### 2.4 AI 模型与部署信息

| 信息             |       是否必须 | 默认假设                                                           |
| ---------------- | -------------: | ------------------------------------------------------------------ |
| 使用模型         | 开发前建议确认 | 支持 OpenAI-compatible API，默认 DeepSeek/Qwen/OpenAI 任一兼容模型 |

## 3. 默认工程假设

为了保证 AI 代码生成可执行，开发阶段采用以下默认假设：

1. 第一版是单品牌自用系统，不做复杂多租户。
2. `user_id` 来自 Header 或本地登录系统，用于数据隔离和审计。
3. PostgreSQL 是主业务数据库。
4. Redis + BullMQ 做异步任务。
5. MinIO 保存素材和操作截图。
6. pgvector 优先，Qdrant 作为后续可选替代。
7. 全部平台先支持 Mock Provider，确保 E2E 全链路可测。
8. 可用的官方 API 优先走 Real Connector。
9. 不稳定的平台能力走 Browser Assist 或 Manual Confirm。
10. MediaCrawler 只做公开数据低频采集，不采集私信和非公开数据。
11. AI 回复默认是“建议回复”，只有低风险消息允许自动回复。
12. 高意向线索必须推送飞书和企微，不允许只停留在系统内。

---

## 4. 当前阶段不建议做的事情

1. 不建议一开始承诺 6 平台全部官方 API 全自动发布。
2. 不建议把飞书多维表格当主数据库。
3. 不建议把 MediaCrawler 当私信采集工具。
4. 不建议做大规模采集或对外售卖数据采集能力。
5. 不建议把 n8n / Dify / Flowise 作为主业务后端。
6. 不建议第一版做复杂多租户计费系统。
7. 不建议让 AI 自动处理高风险投诉、价格承诺、医疗金融法律等敏感回复。
8. 不做内置 AI 生图、生视频、视频剪辑、数字人、配音、字幕自动生成等多媒体生成能力。

---

## 5. 是否可以进入开发？

可以。

建议按以下顺序进入：

```text
PRD 冻结
→ SDD 技术规格冻结
→ 数据模型和接口契约冻结
→ Mock Provider 先行
→ TDD 测试先行
→ 主系统骨架生成
→ 平台 Provider 逐步接入
→ 飞书/企微沉淀
→ E2E 验收
```
