# 02. AI 全域内容获客运营系统技术架构设计 v9

## 1. 架构目标

本系统面向单品牌/单公司自用，要求在平台接口不完全稳定的情况下，仍然保证主业务流程可运行、可测试、可降级、可追踪。

技术目标：

1. 本地优先保存数据。
2. 支持 6 个平台图文和视频素材发布；当前素材由用户上传或外部导入，未来可通过插件式 Media Generation Provider 接入生图/生视频。
3. 支持官方 API、浏览器辅助、手动确认、Mock 四种模式。
4. 支持 MediaCrawler 低频公开数据调研。
5. 支持 AI Skill / Agent 进行文本文案/脚本生成、平台改写、回复建议、意向评分、复盘；当前不做真实图片/视频生成，但预留 Mock/Future Provider 接口。
6. 支持飞书和企业微信沉淀线索。
7. 支持 SDD + TDD 代码生成和验证。

## 1.1 非功能边界：当前不做多媒体生成，未来插件式接入

当前 MVP 只管理和发布用户已有的图片/视频素材，不内置任何真实生图、生视频、视频剪辑、数字人、配音、字幕生成能力。技术架构中当前不得实现以下真实服务，但可以预留接口、枚举、Mock Provider 和 disabled 功能开关：

- image-generation-service
- video-generation-service
- diffusion-runner
- video-renderer
- digital-human-service
- tts/subtitle/auto-editing pipeline

MinIO 当前作为用户上传素材、平台发布截图、导入导出文件和报告的对象存储；未来也可保存生成图片/视频结果。AI Provider 当前仅负责文本生成、分类、摘要、改写和建议；未来多媒体生成必须走独立 MediaGenerationProvider。

#### 5.4.1 Interaction Connector 接口（specs_v1 补充）

#### 5.4.2 平台互动可行性矩阵

| 平台   | 评论拉取 | 私信拉取 | 评论回复 | 私信回复 | 推荐模式                  |
| ------ | -------- | -------- | -------- | -------- | ------------------------- |
| 抖音   | 高       | 中       | 高       | 中       | Official API 优先         |
| 小红书 | 中       | 中       | 中       | 中       | 聚光线索 + Browser Assist |
| 公众号 | 高       | 高       | N/A      | 高       | 官方开发者模式            |
| 视频号 | 中低     | 中低     | 中低     | 中低     | Browser Assist + Manual   |
| 百家号 | 中       | 中低     | 中低     | 中低     | 内容分发为主              |
| 知乎   | 中       | 低       | 中低     | 低       | 调研 + 半自动             |

#### 5.4.3 Reply Policy Engine

规则引擎判断回复策略：

- riskLevel=high → require_human_review
- leadLevel=A → require_human_review
- confidence < 0.75 → require_human_review
- 包含手机号/微信号/外链 → require_human_review
- 平台不支持回复 → manual_only
- 普通 FAQ + low risk + confidence>=0.85 → auto_send

#### 5.4.4 Interaction 新增数据模型

- InteractionClassification: intent, leadLevel, confidence, riskLevel, summary, tags, nextAction
- ReplySuggestion: suggestedText, replyType, riskLevel, needReview, decision
- ReplyAttempt: platform, providerMode, status, externalReplyId, errorCode
- InteractionSyncJob: syncType, mode, status, cursor, fetchedCount

#### 5.4.5 Interaction 状态机

```text
new → classified → reply_suggested → waiting_human_review → replied
new → ignored
classified → converted_to_lead
reply_suggested → replied (低风险自动)
```

ReplySuggestion 状态机：

```text
draft → waiting_review → approved → sent
needReview=true 时不能 draft → sent
riskLevel=high 时必须 waiting_review
```

## 7. Provider Gateway 设计

所有外部平台和开源工具都必须通过 Provider Gateway 调用。

### 7.1 Provider 类型

| Provider                     | 用途         |
| ---------------------------- | ------------ |
| OfficialApiProvider          | 官方 API     |
| BrowserAssistProvider        | 浏览器辅助   |
| MockProvider                 | 开发和演示   |
| ManualImportProvider         | 手动导入     |
| MediaCrawlerResearchProvider | 公开数据调研 |
| SocialAutoUploadProvider     | 视频发布     |
| XiaohongshuSkillProvider     | 小红书 Skill |
| WechatsyncProvider           | 图文同步     |
| FeishuLeadSinkProvider       | 飞书沉淀     |
| WeComLeadSinkProvider        | 企微沉淀     |

### 7.2 Provider 调用原则

1. Provider 不直接访问主数据库。
2. Provider 输入输出必须序列化。
3. Provider 每次调用必须生成 ProviderRunLog。
4. Provider 异常必须捕获。
5. Provider 可替换。
6. Provider 支持 Mock。

### 7.3 ProviderRunLog 字段

```text
id
providerName
providerVersion
operation
inputSummary
outputSummary
status
errorCode
errorMessage
screenshotAssetId
durationMs
startedAt
finishedAt
traceId
```

## 9. Research Runner 架构

### 9.1 定位

Research Runner 独立运行 MediaCrawler，负责单品牌低频公开数据调研。

### 9.2 能力

- searchPosts
- collectPostComments
- collectCreatorPosts
- searchZhihuQuestions
- collectKeywordTrends

### 9.3 边界

允许：公开内容、公开评论、竞品公开账号、关键词搜索。

禁止：私信、非公开数据、绕过验证码、高频批量采集、主动骚扰。

### 9.4 频率控制

| 任务         | 默认频率    |
| ------------ | ----------- |
| 关键词调研   | 每天 1-2 次 |
| 竞品账号同步 | 每天 1 次   |
| 评论样本采集 | 每天 1 次   |
| 知乎问题调研 | 每周 2-3 次 |

必须支持：

- 平台级限频。
- 账号级限频。
- 任务级限频。
- 连续失败熔断。
- 手动暂停。

## 19. 平台发布能力分级与状态机（specs_v1 补充）

### 19.1 发布能力分级

| 模式           | 含义                             | 适用场景                             |
| -------------- | -------------------------------- | ------------------------------------ |
| official_api   | 官方 API 发布                    | 抖音部分能力、公众号、百家号部分能力 |
| browser_assist | 浏览器辅助填充和提交             | 小红书、视频号、知乎、部分百家号     |
| manual_confirm | 系统生成发布清单，人工到平台发布 | 权限不足或风控风险高的平台           |
| sandbox        | 测试账号或测试应用               | 开发/验收环境                        |
| recorded       | 录制真实响应后回放               | 不稳定外部接口测试                   |
| disabled       | 禁用发布                         | 平台未配置或能力不可用               |

### 19.2 平台发布能力矩阵

| 平台       | 图文      | 视频          | 文章/问答 | 推荐 P0 模式                  |
| ---------- | --------- | ------------- | --------- | ----------------------------- |
| 抖音       | 支持/部分 | 支持          | 不适用    | official_api + browser_assist |
| 小红书     | 支持      | 支持          | 不适用    | browser_assist + skill        |
| 微信公众号 | 图文文章  | 视频素材/链接 | 文章      | official_api                  |
| 微信视频号 | 弱        | 视频为主      | 不适用    | browser_assist + manual       |
| 百家号     | 图文      | 视频          | 文章      | official/browser_assist       |
| 知乎       | 图文回答  | 视频弱        | 回答/文章 | browser_assist + manual       |

### 19.3 PublishJob 状态机

```text
draft -> scheduled -> queued -> publishing
publishing -> published | failed | waiting_browser_login | waiting_human_confirm
waiting_browser_login -> publishing
waiting_human_confirm -> published | failed
failed -> queued (重试，retryCount < maxRetries)
scheduled/queued -> cancelled
```

规则：

1. cancelled 不能再次发布
2. published 不能重复发布，除非创建新任务
3. browser_assist 模式必须允许 waiting_browser_login
4. manual_confirm 模式必须进入 waiting_human_confirm
5. retryCount 超过 maxRetries 后进入 failed

## 22. AI Skill Engine 与 Provider Gateway 架构（specs_v1 补充）

### 22.1 Skill 执行协议

```ts
export interface SkillRunner {
  run<TInput, TOutput>(input: {
    skillName: string;
    skillVersion?: string;
```

规则：

4. Provider 输出必须经过 schema 校验
5. Provider 能力必须可查询

### 22.3 ProviderMode

```text
real / sandbox / recorded / browser_assist / manual / disabled
```

## 6.5 未来 Media Generation Provider 预留架构

当前 MVP 不实现真实生图/生视频，但系统需要预留以下扩展层，避免后续重构。

```text
Content Ops
  ↓
Media Asset Library
  ↓
MediaGenerationProvider Interface  当前仅 Mock/Disabled
  ↓
Future Providers
  ├── ImageGenerationProvider
  ├── VideoGenerationProvider
  ├── ComfyUIProvider 可选私有化
  ├── ExternalModelApiProvider
  └── CustomerOwnedProvider
  ↓
MinIO + MediaAsset + Review Workflow
```

### 接口草案

```ts
export interface MediaGenerationProvider {
  getCapabilities(): Promise<MediaGenerationCapabilities>;
  generateImage(input: GenerateImageInput): Promise<GeneratedMediaResult>;
  generateVideo(input: GenerateVideoInput): Promise<GeneratedMediaResult>;
  getJobStatus(jobId: string): Promise<MediaGenerationStatus>;
  cancelJob(jobId: string): Promise<void>;
}

export type MediaGenerationCapabilities = {
  generateImage: boolean;
  generateVideo: boolean;
  supportedInputTypes: Array<'text' | 'image' | 'video' | 'brand_guideline'>;
  requiresHumanReview: true;
  costEstimateSupported: boolean;
};
```

### 当前版本实现要求

1. 只实现 `MockMediaGenerationProvider` 和 `DisabledMediaGenerationProvider`。
2. 不接入真实模型，不产生真实图片/视频。
3. 素材库、数据库和状态机要能容纳未来生成素材。
4. 任何生成结果默认 `pending_review`，不允许直接发布。
5. 未来 Provider 失败不能影响内容、发布、线索和复盘主链路。
