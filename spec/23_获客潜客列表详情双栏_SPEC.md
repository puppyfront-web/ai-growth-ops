# 获客潜客列表详情双栏 SPEC

## 1. 背景

spec/21 落地了分页与筛选，但用户视图仍保持"大卡片流"形态：单卡 6-8 行高，一屏仅能浏览 4-5 位潜客，149 位潜客需要大量滚动，信息密度不足（用户反馈"没啥大的变化"）。评论折叠与内边距收紧无法解决形态本身的问题。

本 SPEC 将结果区重构为**列表 + 详情双栏**（master-detail），取代 spec/21 §5.2 的「用户视图/评论列表」双 tab 结构（spec/21 的 API、筛选、分页、focusId 深链全部保留复用）。

## 2. 目标

1. 左栏高密度潜客列表：一屏可扫 15+ 位潜客，点击行在右栏查看完整详情。
2. 右栏详情面板：全量评论（不再需要折叠）、主页资料、命中策略、采集/转客户操作。
3. 筛选与分页状态写入 URL 查询参数（补齐 `docs/interaction-spec.md` §6 的要求）。
4. 深链 `#candidate-{id}` 行为保留：定位所在页并选中该行。

## 3. 非目标

- 不改后端 API 与数据模型（复用 spec/21 的 `/candidates` 接口）。
- 不做键盘 j/k 导航、多选批量操作、列表列自定义。
- 不做拖拽排序（排序仍固定相关度降序）。

## 4. UI 规格

### 4.1 布局

- `lg+`：`grid lg:grid-cols-[minmax(0,2fr)_minmax(0,3fr)]` 双栏。左栏为列表 + 分页；右栏详情面板 `lg:sticky lg:top-4`、`lg:max-h-[calc(100vh-2rem)]` 内部滚动，保证滚动列表时详情常驻可见。
- `<lg`：仅显示列表；点击行以覆盖层展示详情（fixed inset、含关闭按钮、Esc 关闭、关闭后焦点归还），满足 interaction-spec §4 弹层要求。

### 4.2 左栏列表行（新增 `ProspectListRow`）

- 内容：头像缩略（32px，仅展示）、昵称、等级徽标（A/B/C/D 配色沿用）、相关度（tabular-nums）、已转客户徽标；第二行单条评论摘要 `truncate`。
- 交互：整行点击选中；选中态视觉高亮（`border-primary bg-muted/50`）。
- `id="candidate-{id}"` 锚点从卡片迁移到列表行（客户详情页深链、focusId 滚动定位使用）。

### 4.3 右栏详情面板（新增 `ProspectDetailPanel`，取代 `ProspectUserCard`）

- 头部：昵称、主页链接、等级徽标、相关度、评分来源、评论数。
- 信息：为什么是该等级的摘要、匹配关键词、主页资料摘要（粉丝/关注/获赞/位置）、采集状态提示。
- 评论：**全量展示**（面板内滚动），每条含「优先跟进」标记、点赞数、命中策略、来源视频；不再折叠。
- 操作：头像按钮触发采集主页资料（沿用现有 aria-label/title/禁用规则）；未转化显示「转客户」，已转化显示「已转客户」链接。
- 空选中态：提示「从左侧选择潜客查看详情」。

### 4.4 选中逻辑

- 无选中且当前页非空 → 自动选中首位（首次进入即可看到头部潜客详情）。
- 深链 `#candidate-{id}`：沿用 spec/21 的 focusId 预查询定位页码，数据到位后选中该行并 `scrollIntoView`。
- 筛选/翻页后选中项不在当前页 → 置空（→ 触发自动选首位）。

### 4.5 URL 状态同步

- `q/minScore/leadLevel/converted/page/pageSize` 写入查询参数；初始化时从 URL 恢复。
- 变更通过 `router.replace`（`scroll: false`）更新，`q` 输入防抖 300ms，避免每键一次历史记录。
- `#candidate-` hash 保留不破坏。

## 5. 验收标准

1. `lg+` 视口：左栏一屏可见 ≥ 10 行；点击任一行右栏即时切换详情；滚动列表时详情面板保持可见。
2. 1280px 视口下进入页面自动展示第一位潜客详情，无需先点击。
3. 刷新页面或分享带筛选参数的链接，筛选与页码不丢。
4. 客户详情页「来源潜客」深链：跳到对应页、选中该行并滚动可见。
5. 转客户闭环（e2e flow-deal-close-loop）在双栏下无需修改即可通过。
6. `pnpm typecheck`、`pnpm lint`、单测/web/e2e 通过。
