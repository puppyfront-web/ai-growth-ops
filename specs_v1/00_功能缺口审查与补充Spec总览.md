# AI 全域内容获客运营系统｜功能缺口审查与补充 Spec 总览 v1.0

> 目标：在已有 PRD / 技术架构 / 前端 Spec / 测试 Spec / 评论私信 Spec 的基础上，继续查找类似“有业务概念但缺少工程级实现设计”的模块，并补齐完整功能设计、数据模型、API、状态机、队列、前端页面与测试验收。

---

## 1. 审查结论

之前主 Spec 已经覆盖了整体业务闭环：

```text
市场调研 → 内容策划 → 素材管理 → 多平台发布 → 评论私信 → 意向识别 → 飞书/企微沉淀 → 数据复盘
```

但是除「评论/私信拉取与回复」之外，还有若干模块也存在类似问题：

> 产品层已经提到，但工程实现层还不够细；如果直接交给 AI 生成代码，容易做成“页面有了，按钮不能真实跑通”。

本次补充重点模块如下：

| 序号 | 模块                                | 之前已有程度       | 需要补齐的工程设计                                                                |
| ---- | ----------------------------------- | ------------------ | --------------------------------------------------------------------------------- |
| 1    | 平台发布与 Browser Assist           | 有发布任务概念     | 需要补齐发布状态机、平台能力矩阵、Provider 合同、人工确认流程、发布日志、失败重试 |
| 2    | Research Ops / MediaCrawler         | 有调研概念         | 需要补齐采集任务、限频、熔断、公开数据边界、采集结果入库、洞察生成、选题转内容    |
| 3    | 飞书/企微 Lead Sink                 | 有沉淀概念         | 需要补齐字段映射、幂等同步、失败重试、外部 ID 映射、销售分配、状态回写            |
| 4    | 素材库与未来媒体生成接入            | 有素材库和未来预留 | 需要补齐素材生命周期、审核状态机、对象存储、未来生成 Provider 边界                |
| 5    | AI Skill Engine 与 Provider Gateway | 有 Skill 概念      | 需要补齐 Skill 执行协议、输入输出 Schema、运行日志、Provider 隔离、版本管理       |
| 6    | 内容生命周期与平台版本              | 有内容和平台改写   | 需要补齐 ContentItem / ContentVariant 生命周期、合规检测、发布前检查              |
| 7    | 自动化任务中心与通知                | 有队列概念         | 需要补齐任务中心、重试策略、用户可见任务状态、告警通知                            |
| 8    | 数据复盘与归因                      | 有复盘页面         | 需要补齐事件采集、归因规则、聚合任务、指标口径                                    |
| 9    | 权限、审计与密钥安全                | 有基础设置         | 需要补齐 RBAC、AuditLog、Secret 加密、危险操作审批                                |
| 10   | 本地数据、导入导出与备份            | 有本地优先         | 需要补齐导入导出格式、备份恢复、数据清理策略                                      |

## 4. 总体工程原则

所有补充模块必须遵守以下原则：

```text
1. 不使用前端 Mock 数据。
2. 前端按钮必须调用真实 API。
3. API 必须写入真实数据库。
4. 外部平台不可控时，使用 sandbox / recorded / manual / browser_assist / disabled provider。
5. 所有 Provider 必须有 Contract Test。
6. 所有状态机必须有单元测试。
7. 所有异步任务必须有任务日志和重试策略。
8. 所有关键动作必须有 AuditLog。
9. 所有高风险动作必须人工确认。
10. 核心数据必须保留在本地数据库和对象存储中。
```

## 5. 最终目标

补齐后，系统不是“能展示页面”，而是：

```text
每个页面按钮真实可执行；
每个核心流程真实入库；
每个异步任务真实进入队列；
每个 Provider 有可替换实现；
每个失败路径有降级策略；
每个关键动作可审计；
每个 P0 功能有测试验证。
```
